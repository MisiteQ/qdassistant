# 异地浏览器授权回调「打不开」问题 · 排查结论（2026-10-15）

## 现象

异地电脑浏览器完成 Trae 授权后，跳转到
`http://127.0.0.1:17388/authorize?isRedirect=true&scope=trae&authCodeInfo=%7B%22AuthCode%22...`
报 360 浏览器错误页「您访问的网页出错了！网络连接异常、网站服务器失去响应」。

## 结论：预期行为，不是 Bug

浏览器里的 `127.0.0.1` **永远指浏览器所在的那台电脑**。QDAssistant 跑在 NAS 上，
用户在另一台电脑的浏览器里完成授权，浏览器自然找不到 NAS 上的 17388 —— 必然打不开。

**这正是本项目设计的「授权与入库分离」流程**（`app/core/oauth.py`）：

1. 面板点「OAuth 登录」→ QDAssistant 拼好带 `auth_callback_url=http://127.0.0.1:17388/authorize`
   的 Trae 授权页链接，浏览器打开；
2. 授权成功 → Trae 302 到 `127.0.0.1:17388/authorize?isRedirect=true&scope=trae&authCodeInfo={...}` → 打不开（预期）；
3. **复制地址栏完整 URL → 粘贴回 QDAssistant 输入框** → `trae_oauth_callback()` 解析
   `authCodeInfo` / JWT → ExchangeToken 换取凭据 → 入库。

前端在打开授权页时已给出提示（`app/www/app.js:322`：「授权后浏览器会跳转到
`…redirectUri…` 的打不开页面（正常现象）——复制地址栏完整 URL 粘贴回输入框」）。

## 佐证（本机排查实录）

- 地址栏放大 5 倍复核：端口是 **17388**（与 `oauth.py:50` 完全一致），不是 1738；
- 本机 Trae CN 3.4.3 登录回调端口为**动态分配**（当日实测 6619、7405），从不用 17388
  → 排除「本机 Trae 生成的链接」；
- 系统代理关闭（ProxyEnable=0）且排除列表含 127.0.0.1 → 与代理无关；
- ⚠️ AuthCode 有效期仅 **10 分钟**（Trae 返回 `ExpireDuration: 600000`），粘贴要尽快。

## 使用要点（异地场景）

- 授权完成后**页面报错不用管**，直接全选地址栏复制整条 URL 粘回面板即可；
- 手机浏览器打开授权链接同样可行，粘回时注意别丢 `%7B…%7D` 编码段；
- 回调链接含 AuthCode（一次性凭证），**不要外发**；泄露则重登一次作废旧码。

## 可选改进（backlog 候选）

1. **引导更醒目**：授权前弹层明确告知「接下来会出现打不开的页面，请复制地址栏回填」，
   面板提供「粘贴回调 URL」大输入框 + 10 分钟倒计时提示；
2. **回填体验**：粘贴后即时校验（AuthCode 格式 / 是否过期），过期时提示重新授权而非报错堆栈；
3. **跨设备自动回调**（受 Trae 侧限制，暂不建议）：除非 Trae 允许自定义
   `auth_callback_url` 的 host，否则保持「手动粘贴」是最稳方案；
